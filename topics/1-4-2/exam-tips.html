1.4.2 Data structures • Exam tips

1.4.2 exam tips

What examiners look for in data structure questions, with weak and good answers for each type of question.

Where it comes up

Data structures appear on Paper 1, and again on Paper 2 through algorithms (2.3.1). Trees alone appeared in every series from 2018 to 2022.

What the examiner looks for

Rewarded

  • Precise key terms: LIFO, FIFO, pointer, null, collision, vertex, edge.
  • Steps in order for operations, with the check first (full / empty).
  • Using the diagram or data in the question – name the actual nodes and values.
  • Comparisons as pairs: “a tree has a root, whereas a graph does not”.
  • Big O to back up “faster” or “more efficient”.
  • A judgement at the end of discuss/evaluate questions.

Loses marks

  • Describing operations without saying which pointer changes.
  • A blank or 0 for a null pointer – write −1 or null.
  • Mixing up stack/queue, overflow/underflow, BFS/DFS.
  • Giving in-order when post-order is asked.
  • General answers with no link to the scenario.
  • “Faster” or “better” with no reason.

Weak and good answers

Question: Describe how an item is added to a stack. [3]

Weak answer 1 mark

You put the item on the top of the stack.

Good answer 3 marks

First check whether the stack is full (top = size − 1); if it is, report overflow. Otherwise add 1 to the top pointer, then store the item at stack[top].

How to turn the weak answer into a good one:

  • Start with the check for a full stack.
  • Say what happens to the pointer, not just the item.
  • Give the steps in the right order: move top, then store.

Question: Explain why a queue is suitable for storing jobs sent to a shared printer. [2]

Weak answer 1 mark

A queue is FIFO.

Good answer 2 marks

A queue is FIFO, so jobs are printed in the order they were sent, which is fair to every user of the printer.

How to turn the weak answer into a good one:

  • Don’t stop at the key term – explain what it means for this scenario.
  • Use “so” to link the property to the printer.

Question: Give two similarities and two differences between a tree and a graph. [4]

Weak answer 1 mark

Both have nodes. A tree looks like a family tree and a graph is like a chart.

Good answer 4 marks

Both are made of nodes joined by edges, and both are non-linear. A tree has a root, whereas a graph does not. A graph can contain cycles, whereas a tree cannot.

How to turn the weak answer into a good one:

  • Each difference needs both structures in one sentence – use “whereas”.
  • Avoid descriptions like “looks like a chart” – use structural features.

Question: Explain why searching a balanced binary search tree is more efficient than searching a linked list. [2]

Weak answer 0–1 mark

A BST is faster because it is sorted.

Good answer 2 marks

Each comparison in a BST discards about half of the remaining nodes, so search is O(log n), whereas a linked list must be checked node by node from the head, which is O(n).

How to turn the weak answer into a good one:

  • Say why it is faster: half the tree is discarded each step.
  • Back it up with Big O for both structures.

Question: A hash table uses linear probing. Explain why removing an item should not simply empty its slot. [2]

Weak answer 0 marks

Because the item would be lost.

Good answer 2 marks

A search for a key that was probed past this slot would stop at the empty slot and wrongly report the key as missing. Marking the slot DELETED makes searches continue past it.

How to turn the weak answer into a good one:

  • Explain the consequence for later searches.
  • Give the fix: a DELETED marker.

Planning a long answer (6–9 marks)

  1. Know (AO1): explain how each structure or method works, using key terms (queue, stack, level, backtrack).
  2. Apply (AO2): use the data in the question – write out traversal orders, calculate matrix sizes.
  3. Evaluate (AO3): weigh up memory, speed and suitability for this scenario.
  4. Conclude: make a judgement and give the reason. Answers with no evaluation are capped in the lower bands.
