1.4.2 Data structures

How data is organised so programs can store, find and change it efficiently. Choosing the right structure is a key exam and NEA skill.

What the spec says

  1. Arrays (up to 3 dimensions), records, lists, tuples.
  2. Linked list, graph, stack, queue, tree, binary search tree, hash table.
  3. How to create, traverse, add to and remove from these structures.

Choosing the right structure

If the question says…Think…
“most recent first”, undo, backtrackStack
“in the order they arrived”, buffer, print jobsQueue
“look up by a unique key”Hash table
“kept in order” and searched quicklyBinary search tree
“connections”, routes, networksGraph
“frequent inserts and deletes”, size changesLinked list
“many items of the same type”, access by positionArray
StructureSearchInsertKept in order?
ArrayO(n)O(1) at endYes
Linked listO(n)O(1) at headNot usually
Hash tableO(1) averageO(1) averageNo
BST (balanced)O(log n)O(log n)Yes (in-order)

An unbalanced BST, or a hash table with many collisions, can fall to O(n).

Key terms flashcards

Question

Mixed quiz: which structure?

Mixed quiz – marked for you

1. A text editor needs an undo feature. AO2

Undo reverses the most recent action first: LIFO, so a stack.

2. A phone book must find a number instantly from a person’s name. AO2

Lookup by a unique key: a hash function gives the location directly, O(1) on average.

3. Keystrokes must be processed in the order they were typed. AO2

In the order they arrived: FIFO, so a queue (a keyboard buffer).

4. A sat-nav stores junctions and the roads between them. AO2

Junctions are vertices and roads are weighted edges: a graph.

5. A contact list must be searched quickly and printed A to Z. AO3

A BST gives O(log n) search when balanced, and an in-order traversal prints in sorted order. A hash table is fast but not ordered.

6. An RGB colour value (255, 128, 0) must never be changed by the program. AO2

Fixed data that must never change: an immutable tuple.
