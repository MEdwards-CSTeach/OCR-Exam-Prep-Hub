Hash tables

A hash function turns a key into an index for fast lookup.

What is a hash table?

  • Stores key–value pairs.
  • A hash function turns a key into an array index (the hash value).
  • Go straight to the slot: average search, insert and delete are O(1).
  • Simple hash: key MOD tableSize. For strings, add the ASCII codes then MOD.
  • A good hash function is quick, always gives the same index for a key, and spreads keys evenly.

Example: table of 7 slots
hash(15) = 15 MOD 7 = 1
hash(23) = 23 MOD 7 = 2
hash("Jo") = (74 + 111) MOD 7 = 185 MOD 7 = 3

Collisions

Linear probing

  • If the slot is taken, try the next one: index = (index + 1) MOD size.
  • All data stays in the array.
  • ✗ Clustering: items bunch together, so searches get slower.
  • Searching must also probe on until it finds the key or an empty slot.

Chaining

  • Each slot holds a linked list; colliding items are added to it.
  • ✓ No clustering; can hold more items than slots.
  • ✗ Extra memory for pointers; long chains are slow to search.

Load factor and table size

  • Load factor = items ÷ slots. 5 items in 7 slots = 0.71.
  • Higher load factor = more collisions. Keep it at or below about 0.7.
  • Use a prime table size – it spreads keys that follow a pattern (e.g. 10, 20, 30…).
  • When too full, resize and rehash: make a bigger table and re-insert every item, because the index depends on the size.

Uses: Python dictionaries, database indexes, caches, compiler symbol tables, password storage. Quick test: “look up by a unique key” = hash table.

Watch out for:

  • Emptying a slot on delete – searches would stop early and miss items. Use a DELETED marker.
  • Forgetting to wrap round with MOD when probing.
  • Saying a hash table keeps data in order – it doesn’t.
  • Forgetting that resizing means rehashing every item.

Quick quiz – marked for you

1. A hash table has 7 slots and uses key MOD 7. Which index does key 31 hash to? AO2

31 ÷ 7 = 4 remainder 3, so 31 MOD 7 = 3.

2. Hash the string "CAT" by adding ASCII codes (C = 67, A = 65, T = 84) then MOD 11. What is the index? AO2

67 + 65 + 84 = 216. 11 × 19 = 209, so 216 MOD 11 = 7.

3. A table has 8 slots and holds 5 items. What is the load factor? AO2

Load factor = items ÷ slots = 5 ÷ 8 = 0.625 (62.5% full).

4. Slots 3 and 4 hold 10 and 31 (31 was probed from 3). Why must removing 10 mark slot 3 as DELETED, not empty? AO3

Searches stop at an empty slot. A DELETED marker tells the search to keep probing, so 31 is still found.

5. Why is a prime number often chosen for the table size? AO1

A prime shares no factors with patterns like 10, 20, 30…, so these keys spread across different slots instead of colliding.

Exam-style questions – mark them yourself

Write your answer, then open Mark your answer. Tick the mark points you hit, read the model answer and use the tips to improve. See the 1.4.2 exam tips for more help.

AO1[2 marks]

State what is meant by a collision in a hash table and name one way to deal with it.

Mark your answer

Tick each mark point your answer includes.

Model answer: A collision is when two different keys hash to the same index. It can be dealt with by linear probing: storing the item in the next free slot.

How to improve a weak answer:

  • Say different keys – the same key twice is an update, not a collision.
AO2[4 marks]

A hash table has 7 slots (0–6), uses key MOD 7 and linear probing. Show where the keys 14, 22, 8 and 29 are stored, inserted in that order.

Mark your answer

Tick each mark point your answer includes.

Model answer: 14 MOD 7 = 0, so 14 goes in slot 0. 22 MOD 7 = 1, so slot 1. 8 MOD 7 = 1, which is taken, so it probes to slot 2. 29 MOD 7 = 1; slots 1 and 2 are taken, so it goes in slot 3.

How to improve a weak answer:

  • Show the calculation for each key – method marks.
  • When probing, say which slots were taken.
  • Notice that 22, 8 and 29 form a cluster.
AO3[4 marks]

Compare linear probing and chaining as ways of handling collisions.

Mark your answer

Tick each mark point your answer includes.

Model answer: With linear probing, a colliding item is stored in the next free slot, whereas with chaining it is added to a linked list at the same index. Linear probing causes clustering, so searches slow down as the table fills, while chaining avoids clustering. Chaining can store more items than there are slots, whereas linear probing is limited to the table size. However, chaining needs extra memory for the pointers, and long chains are slow to search.

How to improve a weak answer:

  • “Compare” needs both methods in each point – use “whereas”.
  • Give advantages and disadvantages of each.
