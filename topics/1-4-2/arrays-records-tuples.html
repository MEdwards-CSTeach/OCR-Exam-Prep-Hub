Arrays, records and tuples

Store many items by position, fixed data, or related fields by name.

Key terms

  • Array, element, index
  • Dimension (1D, 2D, 3D)
  • Record, field
  • Tuple, immutable
  • Static

  • Links and slides

Arrays

  • An ordered, fixed-size collection of elements of the same data type.
  • Each element is accessed by its index. Indexing usually starts at 0 – check the question.
  • Access by index is instant: no searching needed.
  • Traverse by looping through every index from first to last.
  • Arrays are static: the size is set when created.

2D and 3D arrays

  • A 2D array is a table: an array of arrays. Access with [row][col] or [row, col].
  • Track the row first, then the column.
  • A 3D array adds another dimension, e.g. [day][hour][sensor]. The spec includes up to 3 dimensions.
  • The dimension is how many indexes you need to find one item.
array letters[2,3]
for i = 0 to 1
    for j = 0 to 2
        letters[i, j] = input()
    next j
next i
marks[1][2] = 77 (row 1, column 2)

Records and tuples

Record

  • A collection of related fields, which can be different data types.
  • Accessed by field name: student.name, not student[0].
  • Several different things about one item.
name : "Amelia Khan"   // string
age : 16               // integer
average_score : 78.5   // real

Tuple

  • An ordered collection that cannot be changed once created: immutable.
  • Can hold different data types.
  • Used for fixed data: coordinates (150, 300), RGB colours (255, 128, 0), returning several values.

Which one?

ArrayTupleRecord
StoresMany items, same typeFixed items, any typeRelated fields, any type
Can change?YesNo (immutable)Usually yes
Accessed byIndexIndexField name
Best forMany similar itemsData that must never changeOne thing with many attributes

One-line test: same type, by position = array. Fixed, never changes = tuple. Different types, by name = record. An array of records stores many items, each with several fields.

Watch out for:

  • Check whether indexes start at 0 or 1 in the question.
  • Mixing up row and column in a 2D array – row first.
  • Saying a tuple holds only one data type – it can mix types; an array can’t.

Quick quiz – marked for you

1. Which structure is immutable and can hold different data types? AO1

A tuple cannot be changed once created and can mix types. An array holds one type; a record is usually changeable.

2. Using the marks table above, what is marks[2][1]? AO2

Row 2 is the third row (64, 58, 95, 70). Column 1 is the second value: 58. Remember: row first, then column, both starting at 0.

3. The nested loop above fills letters with inputs a, b, c, x, y, z. What is stored in letters[1,0]? AO2

The inner loop fills row 0 first (a, b, c), then row 1 (x, y, z). letters[1,0] is the first cell of row 1: x.

4. How is data in a record accessed? AO1

Each field in a record has its own name, e.g. student.name. This makes code more readable than student[0].

5. A program must store the (x, y) start position of a game level, which must never change. Which structure fits best? AO3

Fixed data that must never change is a tuple. Immutability stops it being changed by accident elsewhere in the program.

Exam-style questions – mark them yourself

Write your answer, then open Mark your answer. Tick the mark points you hit, read the model answer and use the tips to improve. See the 1.4.2 exam tips for more help.

AO1[2 marks]

Describe two differences between an array and a record.

Mark your answer

Tick each mark point your answer includes.

Model answer: An array stores elements that are all the same data type, whereas a record can hold fields of different data types. Elements of an array are accessed by their index, whereas fields of a record are accessed by name.

How to improve a weak answer:

  • Write each difference as a pair using “whereas” – describing only one structure loses the mark.
  • Use the key terms: data type, index, field name.
AO2[3 marks]

A teacher stores the scores for 30 students in 4 tests. Explain why a 2D array is suitable, and write the expression for the score of the 5th student in the 3rd test. Indexes start at 0.

Mark your answer

Tick each mark point your answer includes.

Model answer: A 2D array suits this because every score is an integer, and the data is naturally a grid with a row for each of the 30 students and a column for each of the 4 tests. The score is scores[4][2].

How to improve a weak answer:

  • Link each reason to the data in the question (30 students, 4 tests).
  • Indexes start at 0, so the 5th student is row 4 and the 3rd test is column 2 – a very common slip.
AO3[4 marks]

A school library stores the title, author, year published and whether it is on loan, for 5,000 books. Justify a suitable data structure.

Mark your answer

Tick each mark point your answer includes.

Model answer: Each book should be a record with fields title (string), author (string), year (integer) and onLoan (Boolean), because the fields have different data types. The 5,000 records should be stored in an array of records, because every book has the same structure, so the program can loop through them to search or display them.

How to improve a weak answer:

  • “Justify” means give a reason for every choice – use “because”.
  • Name the data types of the fields to show the record is the right choice.
  • Say how the many books are stored, not just one book.
