Graphs

Vertices joined by edges. Stored as a matrix or list; searched by BFS or DFS.

Key terms

  • Vertex (node), edge (arc)
  • Directed / undirected
  • Weighted / unweighted
  • Adjacency matrix, adjacency list
  • Sparse, dense
  • BFS (queue), DFS (stack)
  • Revision notes
  • Links and slides

  • Exam questions

What is a graph?

  • A set of vertices (nodes) joined by edges (arcs).
  • Stores relationships: who knows who, which places connect.
  • Directed: edges have a direction (P follows Q). Undirected: both ways.
  • Weighted: edges carry a value (distance, time, cost). Unweighted: just connected or not.
  • Two vertices joined by one edge are adjacent.

Storing a graph

Adjacency matrix

ABCDE
A01100
B10010
C10010
D01101
E00010

Row = from, column = to. Undirected graphs give a symmetric matrix. A weighted graph stores the weight instead of 1.

Adjacency list

A : [B, C]
B : [A, D]
C : [A, D]
D : [B, C, E]
E : [D]

Each vertex lists its neighbours. Weighted: store pairs, e.g. H : [(F, 4), (L, 12)].

Traversing a graph

Breadth-first (BFS)

  • Visit all neighbours first, then their neighbours – level by level.
  • Uses a queue.
  • Finds the shortest path (fewest edges) in an unweighted graph.
  • From A: A, B, C, D, E

Depth-first (DFS)

  • Go as deep as possible along one path, then backtrack.
  • Uses a stack (or recursion).
  • Shortest path not guaranteed; usually uses less memory.
  • From A: A, B, D, C, E

Both need a visited list, or a graph with a cycle loops forever. For weighted shortest paths, use Dijkstra’s or A* (2.3.1). Uses: social networks, sat-navs, web crawlers.

Watch out for:

  • Saying BFS finds the quickest route in a weighted graph – it finds the fewest edges, ignoring weights.
  • Mixing up which uses a queue (BFS) and which uses a stack (DFS).
  • Saying an adjacency list always uses less memory – not for dense graphs.
  • Forgetting an undirected edge must appear in both vertices’ lists.

Quick quiz – marked for you

1. Flights between airports, labelled with ticket prices. What type of graph is this? AO2

A flight from X to Y doesn’t guarantee one back (directed), and each edge has a price (weighted).

2. A road network has 40,000 junctions, each joined to 3 or 4 roads. Which representation is better? AO3

The graph is sparse: a matrix needs 1.6 billion cells, almost all 0. A list stores only the roads that exist.

3. Give the breadth-first order from A for the example graph. Take neighbours in alphabetical order. AO2

Visit A, then its neighbours B and C, then their unvisited neighbour D, then E. Order: A, B, C, D, E.

4. Give the depth-first order from A for the example graph (alphabetical order). AO2

A → B → D (go deep) → C (D’s next unvisited neighbour) → backtrack to D → E. Order: A, B, D, C, E.

5. Which data structure does breadth-first search use? AO1

BFS enqueues neighbours as they are discovered and dequeues them in order (FIFO), so it works level by level.

Exam-style questions – mark them yourself

Write your answer, then open Mark your answer. Tick the mark points you hit, read the model answer and use the tips to improve. See the 1.4.2 exam tips for more help.

AO1[2 marks]

State what is meant by a graph.

Mark your answer

Tick each mark point your answer includes.

Model answer: A graph is a set of vertices (nodes) connected by edges (arcs).

How to improve a weak answer:

  • Two marks = two key terms. Use both vertices and edges.
AO2[3 marks]

Explain why a breadth-first search finds the shortest route in an unweighted graph, but may not find the quickest route in a weighted graph.

Mark your answer

Tick each mark point your answer includes.

Model answer: BFS visits all vertices one edge away, then two edges away, and so on, so it reaches each vertex by the path with the fewest edges. However, it ignores edge weights, so a path with more edges but smaller weights could be quicker. An algorithm such as Dijkstra’s, which uses the weights, is needed for weighted graphs.

How to improve a weak answer:

  • Explain why BFS gives fewest edges (level by level).
  • Give the reason it fails for weighted graphs – it ignores the weights.
AO3[6 marks]

A sat-nav company stores a road network of 40,000 junctions. Each junction connects to 3 or 4 roads, and each road has a travel time. Discuss how the company should store this graph and how it could be searched to find routes.

Mark your answer

Tick each mark point your answer includes.

Model answer: An adjacency matrix would need 40,000 × 40,000 = 1.6 billion cells, but with only around 70,000 roads almost all would be empty, because the graph is sparse. An adjacency list stores only the roads that exist, using far less memory, and each entry can store a (neighbour, travel time) pair. BFS would find the route through the fewest junctions but ignores travel time, and DFS doesn’t guarantee the shortest path at all, though it could check whether any route exists. The company should use an adjacency list with a weighted shortest-path algorithm such as Dijkstra’s or A*.

How to improve a weak answer:

  • Use the numbers in the question – work out the matrix size.
  • Cover both structures and both searches, as the question asks.
  • End with a judgement: which structure and which algorithm, and why. No conclusion caps your mark.

How to revise this

  • Trace tables – trace BFS with the queue and DFS with the stack
  • Comparison tables – matrix vs list; BFS vs DFS
  • Concept maps – link graphs to stacks, queues and 2.3.1 algorithms

These are the best fit for this part of the topic, but you can use any revision technique that works for you.
