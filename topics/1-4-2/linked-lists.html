Lists and linked lists

  • A list stores items in order. Unlike a fixed array, a list can usually grow and shrink.
  • A linked list is a dynamic list made of nodes.
  • Each node holds data and a pointer (next) to the next node.
  • The head points to the first node – your only way in.
  • The last node’s pointer is null (None), marking the end.
  • Nodes can be anywhere in memory – no shuffling when inserting.

Linked list or array?

Linked list ✓

  • Dynamic – grows and shrinks while running
  • Insert and delete by changing pointers – no shuffling

Linked list ✗

  • No direct access by index – must traverse from the head: O(n)
  • Extra memory for each pointer

Uses: music playlists, undo history, browser back/forward (a doubly linked list points both ways).

Watch out for:

  • Moving head (or the previous pointer) first when inserting – the rest of the list is lost.
  • Saying you can “go straight to” an item – you must traverse from the head.
  • Deleting the data but not changing the previous node’s pointer.
  • Writing a blank or 0 for null in a table – use null or −1.

Quick quiz – marked for you

1. What two things does every node in a linked list hold? AO1

A node holds its data and a pointer (next) to the next node. A doubly linked list adds a second pointer to the previous node.

2. What value is stored in the pointer of the last node? AO1

The last node’s pointer is null (None in Python). In an array-based table, −1 is often used. It marks the end of the list.

3. To insert 15 between 10 and 20 (current is the node holding 10), which line must run first? AO2

Point the new node at 20 first. If 10 points to the new node first, nothing remembers where 20 is and the rest of the list is lost.

4. Why can’t you go straight to the 5th node of a linked list? AO2

Nodes can be anywhere in memory, so there is no index to calculate. You must traverse from the head, following each pointer: O(n).

5. This code should add a node to the end: while current != null: current = current.next then current.next = new. What is wrong? AO3

The loop runs past the last node. Fix: while current.next != null, so it stops ON the last node.

Exam-style questions – mark them yourself

Write your answer, then open Mark your answer. Tick the mark points you hit, read the model answer and use the tips to improve. See the 1.4.2 exam tips for more help.

AO1[2 marks]

State what is meant by a node and by the head of a linked list.

Mark your answer

Tick each mark point your answer includes.

Model answer: A node is one item in the list, holding the data and a pointer to the next node. The head is a pointer to the first node in the list.

How to improve a weak answer:

  • “State” needs a short, precise answer – use the key terms data and pointer.
AO2[3 marks]

A linked list holds 10 → 20 → 30. Describe how the node containing 20 is removed.

Mark your answer

Tick each mark point your answer includes.

Model answer: Start at the head and follow the pointers to the node holding 10, the node before 20. Change 10’s pointer so it points to 30 (the node that 20 pointed to). Nothing points to 20 any more, so it is no longer part of the list.

How to improve a weak answer:

  • Use the values from the question (10, 20, 30) in every step.
  • Say which pointer changes and what it now points to – “delete 20” alone gets no marks.
AO3[4 marks]

A games leaderboard is read thousands of times a minute but changes rarely. Discuss whether it should be stored as an array or a linked list.

Mark your answer

Tick each mark point your answer includes.

Model answer: An array lets the program go straight to any position using its index, which is O(1), whereas a linked list must be traversed from the head, which is O(n). A linked list would be better if scores were inserted often, because new nodes can be linked in without shuffling. However, the leaderboard is read constantly and rarely changed, so an array is the better choice.

How to improve a weak answer:

  • Weigh both options, then decide – a “discuss” answer needs a conclusion.
  • Back up “faster” with Big O.
  • Link the conclusion to the scenario: read often, changed rarely.

How to revise this

  • Teach it – explain insert and delete out loud, drawing the arrows
  • Flowcharts and process diagrams – draw before-and-after diagrams for each operation
  • Trace tables – trace a traversal loop node by node

These are the best fit for this part of the topic, but you can use any revision technique that works for you.
