How classes relate

Inheritance: “is a”

A Dog is a Pet. A Teacher is a Person. The subclass gets everything the superclass has. In Python: class Dog(Pet):

Association: “has a” / “uses”

A Team has Players. A Driver uses a Car. One object stores another as an attribute. In Python: self.__players = []

Beyond the spec: aggregation – the parts can exist alone (a playlist’s songs); composition – the parts die with the whole (a house’s rooms).

Finding the classes in a scenario

  1. Nouns: underline them – they are candidate classes.
  2. Filter: is it a thing with data and behaviour, or just a value? Values become attributes.
  3. Verbs: these become methods.
  4. Relate: “is a” → inheritance; “has a” → association.

Worked example: “A school library lends books and DVDs to members. Every item has a title and a barcode. A member can borrow up to 5 items.”

  • Classes: Library, Item, Book, DVD, Member
  • title, barcode → attributes of Item
  • lend, borrow → methods
  • Book is an Item; DVD is an Item; Library has Items and Members

Has a, in code

class Team:
    def __init__(self, name):
        self.__name = name
        self.__players = []        # has a: Players

    def addPlayer(self, player):
        self.__players.append(player)

    def listPlayers(self):
        for p in self.__players:
            print(p.getName())
  • Team is not Team(Player) – a team is not a player.
  • __players is a list of Player objects: Team has Players.
  • Team asks each Player for its name with getName() – it can’t read the private attribute.
  • If each object has its own overridden describe(), a loop over the list shows polymorphism – no if statements needed.

Watch out for:

  • Using inheritance for “has a”: a Team should not inherit from Player.
  • Making every noun a class – values like title or price are attributes.
  • Inheriting in the wrong direction: check “a Square is a Shape”, not the reverse.
  • A 12-mark discussion with definitions but no examples from the scenario.

Quick quiz – marked for you

1. Car and Engine: which relationship? AO2

A car has an engine. An engine is not a car.

2. Square and Shape: which relationship? AO2

A square is a shape, so Square inherits from Shape.

3. Student and Teacher: which relationship? AO3

A student isn’t a teacher, and neither contains the other. Both are a Person.

4. How do you find candidate classes in a scenario? AO1

Nouns are candidate classes; verbs become methods; simple values become attributes.

5. Which Python line makes Dog a subclass of Pet? AO1

The superclass goes in the brackets: class Dog(Pet):

6. In a library system, “title” is best modelled as… AO2

A title is a single value with no behaviour of its own, so it is an attribute.

Premium gym members also have a trainer. Explain how inheritance can be used.

Mark your answer

Tick each mark point your answer includes.

Model answer: Create a subclass PremiumMember that inherits from Member. It takes on name, age, visits and all of Member’s methods without them being written again. It adds a private trainer attribute, with get and set methods.

How to improve a weak answer:

  • Name both classes from the scenario.
  • Say what is inherited and what is added.
AO2[3 marks]

Explain how encapsulation can stop a member’s age being set below 16.

Mark your answer

Tick each mark point your answer includes.

Model answer: The age attribute is made private, so no code outside the class can change it directly. A public setAge method is the only way to change it, and it only accepts values of 16 or more.

How to improve a weak answer:

  • Each mark is one idea, linked to Member and age.
AO3[12 marks]

Discuss the advantages of object-oriented programming over procedural programming when developing computer games. Refer to inheritance, encapsulation and polymorphism. (November 2020)

Mark your answer

Tick each mark point your answer includes.

Model answer: Polymorphism means the same method call behaves differently for objects of different classes. In the game, Zombie and Ghost could both override the move() method of Enemy, so the main loop just calls move() on every enemy and each one moves in its own way. So new enemy types can be added without changing the game loop, whereas a procedural version would need another if statement in every movement procedure, which is harder to maintain and more likely to contain errors. (Write one paragraph like this for each pillar, then weigh up the drawbacks and conclude.)

How to improve a weak answer:

  • Each paragraph: point (definition) → game example → so what, compared with procedural.
  • Use named classes and methods from the game.
  • End with a judgement for this context – games are large systems of interacting things.

How to revise this

  • Concept maps – draw is-a and has-a links between classes
  • Planning extended answers – the 12-mark OOP vs procedural question
  • Worked examples – turn a scenario into classes step by step
