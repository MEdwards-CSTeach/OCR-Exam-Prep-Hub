Recursion vs iteration

When recursion is the right tool, how it compares with iteration, and how to rewrite a recursive function as a loop.

So why use recursion?

For factorial, a loop is just as easy. Recursion earns its place when a problem is made of smaller copies of itself.

Nested data

Folders in folders, family trees, HTML tags inside tags. Depth unknown.

Divide and conquer

Binary search, merge sort, quick sort: split in half and solve each half the same way (2.3.1).

Branching and backtracking

Mazes, sudoku, game AI that looks ahead, flood fill, fractals.

Rule of thumb: if you would need an unknown number of nested loops, think recursion.

Recursion compared with iteration

RecursionIteration
HowThe function calls itselfA loop repeats code
MemoryEach call adds a stack frame: new variables each timeReuses the same variables
RiskCan run out of stack space: stack overflowCannot run out of stack space
SpeedOften slower: pushing and popping frames takes timeOften faster
CodeShorter and more elegant for self-similar problemsLonger and harder to follow for those problems
TracingHarder to trace and debugEasier to trace

Compare = a point about recursion + the matching point about iteration. Use “whereas”. The big test: adding 1 to 5000 recursively overflows Python’s stack; the loop gives 12502500.

Same job, both ways: folder size

Recursive

def folder_size(folder):
    total = 0
    for item in folder:
        if type(item) == list:
            total = total + folder_size(item)
        else:
            total = total + item
    return total

A sub-folder is the same problem, smaller. Works for any depth.

Iterative

def folder_size_iterative(folder):
    total = 0
    to_visit = [folder]
    while len(to_visit) > 0:
        current = to_visit.pop()
        for item in current:
            if type(item) == list:
                to_visit.append(item)
            else:
                total = total + item
    return total

Needs its own stack. Recursion is a stack the computer manages for you.

photos = [12, 5, [3, 8, [20]], 7] gives 12 + 5 + (3 + 8 + 20) + 7 = 55 both ways.

Rewriting recursion as a loop (June 2019)

Recursive

function GCD(num1, num2)
    if num2 == 0 then
        return num1
    else
        return GCD(num2, num1 MOD num2)
    endif
endfunction

Iterative

function newGCD(num1, num2)
    while num2 != 0
        temp = num2
        num2 = num1 MOD num2
        num1 = temp
    endwhile
    return num1
endfunction
  1. Keep the same function header.
  2. The base case becomes the loop’s stopping condition.
  3. The recursive call’s new values become variable updates.
  4. Return after the loop.

Common bugs: if len(word) == 1 overflows on "" (use <= 1); returning a sub-folder’s answer straight away stops later folders being searched. Test the base case, a deep item and an item in the last branch.

Watch out for:

  • Only one side of a comparison – say what recursion does whereas iteration…
  • “Recursion is faster” – it is usually slower.
  • Rewrites with no loop, no return, or a changed function header.
  • Forcing recursion onto flat data such as averaging 30 scores.

AO1[4 marks]

Compare two differences between recursion and iteration. (November 2020)

Mark your answer

Tick each mark point your answer includes.

Model answer: Recursion uses more memory because every call adds new variables to the stack, whereas iteration reuses the same variables. Recursion can run out of stack space, whereas iteration cannot.

How to improve a weak answer:

  • Every point needs its matching opposite: “recursion… whereas iteration…”.
  • “Recursion loops back to itself” is wrong – it calls itself.
AO2[4 marks]

Rewrite calculate() using iteration.

function calculate(number)
    if number == 1 then
        return number
    else
        return number + calculate(number - 1)
    endif
endfunction
Mark your answer

Tick each mark point your answer includes.

Model answer: function calculate(number)
  total = 0
  for i = 1 to number
    total = total + i
  next i
  return total
endfunction

How to improve a weak answer:

  • Keep the header – the question is about the same function.
  • The return goes after the loop, not inside it.
  • Test it with a small value such as 3 (should give 6).
AO3[4 marks]

A program finds every file on a school network drive, where folders can contain folders to any depth. Evaluate whether recursion or iteration is more suitable.

Mark your answer

Tick each mark point your answer includes.

Model answer: Recursion suits this because each folder is a smaller copy of the same problem and the depth is unknown, so a fixed set of loops wouldn’t work. The recursive code is short, whereas an iterative version must manage its own stack. However, every call adds a stack frame, so an extremely deep folder structure could cause a stack overflow. Overall recursion is more suitable, because real folder structures are rarely deep enough to fill the stack.

How to improve a weak answer:

  • Evaluate = both sides + a judgement for this scenario.
  • Link each point to folders, not just general facts.
