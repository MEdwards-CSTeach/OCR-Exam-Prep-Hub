Recursion: how it works

A subroutine that calls itself: base case and general case, winding and unwinding, the call stack and how to trace it.

What is recursion?

Recursion is when a subroutine calls itself. The problem is solved by solving a smaller version of the same problem, until the problem is so small the answer is obvious.

1. Base case

The stopping condition. Returns an answer without calling itself.

2. General case

Also called the recursive case. Calls itself with a smaller problem.

3. Moves to the base case

Each call must get closer to the base case, or it never stops.

OCR pseudocode

function factorial(n)
    if n == 1 then
        return 1                      // base case
    else
        return n * factorial(n - 1)   // general case
    endif
endfunction

Python

def factorial(n):
    if n == 1:
        return 1
    else:
        return n * factorial(n - 1)

4! = 4 × 3!, so a factorial is made of a smaller factorial. n - 1 moves towards 1.

Winding and unwinding

The call stack

  • Every call pushes a stack frame: its parameters, local variables and the return address.
  • Each call has its own copy of n.
  • When a call returns, its frame is popped off the top.
  • The stack has limited space. Too many calls fill it: stack overflow (Python allows about 1000).
  • No base case, or one that is never reached (e.g. factorial(0)), means the calls never stop.

Exam point: each recursive call stores its state on the stack, whereas iteration reuses the same variables.

Writing and tracing a recursive function

Three steps to write one

  1. Base case first: the smallest input you can answer straight away.
  2. General case: trust the function to work on a smaller input. How do you use that answer?
  3. Check: does every call get closer to the base case? Test 0, 1 and "".
def list_total(numbers):
    if len(numbers) == 0:
        return 0
    else:
        return numbers[0] + list_total(numbers[1:])

list_total([4, 7, 2]) = 4 + 7 + 2 + 0 = 13

Four steps to trace one

  1. Going down: write each call and what it is waiting for.
  2. Stop at the base case.
  3. Going up: fill in each return, bottom row first.
  4. The answer is the top row.

Full-mark trace: June 2018 (watch the DIV)

function generate(num1 : byval)
    if num1 > 10 then
        return 10
    else
        return num1 + (generate(num1 + 1) DIV 2)
    endif
endfunction
CallReturns
generate(11)base case: 10
generate(10)10 + 10 DIV 2 = 15
generate(9)9 + 15 DIV 2 = 9 + 7 = 16
generate(8)8 + 16 DIV 2 = 16
generate(7)7 + 16 DIV 2 = 15

15 DIV 2 = 7. Using 7.5 breaks every line after it.

Watch out for:

  • Giving the base case value (1) as the final answer – the answer is what the first call returns.
  • Forgetting DIV is whole-number division: 15 DIV 2 = 7.
  • Describing recursion as “it loops” – it calls itself.
  • A base case of == 1 that is skipped by an input of 0, so the stack overflows.

Quick quiz – marked for you

1. What does the base case do? AO1

The base case is the stopping condition.

2. While factorial(2) is running, what is factorial(3) doing? AO1

It waits on the stack until the call below it returns.

3. Which call finishes first in factorial(4)? AO2

The last call made is the first to finish: last in, first out.

4. What happens if the base case is removed? AO2

The calls never stop, so the call stack runs out of space.

5. calculate(n) returns n if n == 1, otherwise n + calculate(n − 1). What does calculate(5) return? AO2

5 + 4 + 3 + 2 + 1 = 15 (June 2022).

6. Using the generate function above, what does generate(9) return? AO2

generate(10) returns 15, and 15 DIV 2 = 7, so 9 + 7 = 16.

AO3[2 marks]

Explain what would happen if calculate(0) were called, and how it could be prevented.

Mark your answer

Tick each mark point your answer includes.

Model answer: The values 0, −1, −2 and so on never equal 1, so the base case is never reached and the function keeps calling itself until the call stack runs out of space – a stack overflow. Changing the base case to if number <= 1 would stop it.

How to improve a weak answer:

  • Explain = what happens + the consequence. “It crashes” alone is only half.
  • Suggest a precise fix, not just “add validation”.

How to revise this

  • Trace tables – trace recursive calls down and the returns back up
  • Flowcharts and diagrams – draw the winding and unwinding staircase
  • Flashcards – base case, general case, stack frame, stack overflow

These are the best fit for this part of the topic, but you can use any revision technique that works for you.
