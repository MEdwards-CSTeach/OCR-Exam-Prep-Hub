Encapsulation

Encapsulation bundles an object’s attributes and methods together and hides the attributes, so they can only be changed through the object’s own methods.

KeywordMeaning
privateOnly code inside the class can use it. Attributes are usually private.
publicAny code can use it. Methods are usually public.
get / setPublic methods that read (get) or change (set) a private attribute. A set method can validate.

Why? Data can’t be changed by accident or set to an invalid value.

class ItemForSale
    private price
    private discount
    public function getDiscount()
        return discount
    endfunction
    public procedure setDiscount(newD)
        if newD >= 0 AND newD <= 50 then
            discount = newD
        endif
    endprocedure
endclass

November 2020: three steps – make it private, add a set method, validate inside it.

Inheritance

Inheritance lets a subclass take on all the attributes and methods of its superclass, and add or change its own. Write shared code once in the superclass.

OCR pseudocode (October 2021)

class house inherits building
    private bedrooms
    private bathrooms
    public procedure new(pF, pW, pH, pBd, pBt)
        super.new(pF, pW, pH)
        bedrooms = pBd
        bathrooms = pBt
    endprocedure
endclass

houseOne = new house(2, 8, 10, 3, 2)

Python

class House(Building):
    def __init__(self, pF, pW, pH, pBd, pBt):
        super().__init__(pF, pW, pH)
        self.__bedrooms = pBd
        self.__bathrooms = pBt
  • inherits names the superclass.
  • super.new runs the superclass constructor to set the inherited attributes.
  • A subclass can’t see the superclass’s private attributes – it uses get methods.

Polymorphism

Polymorphism means “many forms”: the same method call behaves differently depending on the class of the object. A subclass overrides a method it inherited with its own version.

class Animal
    public function speak()
        return "..."
    endfunction
endclass
class Dog inherits Animal
    public function speak()
        return "Woof"
    endfunction
endclass
class Cat inherits Animal
    public function speak()
        return "Meow"
    endfunction
endclass
for each a in animals
    print(a.speak())
next a

One loop, a different result for each object. New animal types can be added without changing the loop – no if statement for every type.

Which pillar? “Can only be changed by a method” → encapsulation. “Reuses / takes on from a parent” → inheritance. “Same call, different result” → polymorphism.

Watch out for:

  • Defining inheritance without naming both classes from the scenario.
  • Encapsulation answers that miss a step: private, set method, and the validation.
  • Forgetting super.new(…) in a subclass constructor, or not using every parameter.
  • Confusing overriding (polymorphism) with inheriting a method unchanged.

Quick quiz – marked for you

1. Teacher and Student both get name and email from Person. Which pillar? AO2

The subclasses take on attributes from the superclass Person.

2. shape.area() works out a circle and a square differently. Which pillar? AO2

Same method call, different behaviour depending on the object’s class.

3. setAge() refuses −3. Which pillar? AO2

age is private and can only be changed through a set method that validates it.

4. What does super.new(pF, pW, pH) do in a subclass constructor? AO1

It runs the building constructor so that floors, width and height are set.

5. A get method usually… AO1

A get method returns a value. A set method takes a parameter and can validate it.

6. Dog and Cat both override speak(). for each a in animals: print(a.speak()) prints “Woof” then “Meow”. This shows… AO3

One call, and each object answers in its own way. No if statements needed.

Mark your answer
