2.1.3 Thinking procedurally

Breaking a problem down: problem and solution components, hierarchy charts, the order of steps and the sub-procedures you need.

Decomposition

Decomposition is breaking a problem into smaller sub-problems until each one is a single task that can be solved.

Components of the problem (a)

What must happen or what the user needs.

  • The game ends when the snake hits a wall
  • The snake grows when it eats
  • Players can see their high score

Components of the solution (b)

How it will be done in code.

  • saveScore(name, score) – a subroutine
  • A list of positions – a data structure
  • gameOver – a Boolean variable

Hierarchy (structure) charts

  • The top box is the whole problem; each level down splits it further.
  • It shows structure only: no decisions and no loops. For those, draw a flowchart.
  • Different charts can all be correct, as long as every bottom box is one task.

Order of steps (c) and sub-procedures (d)

Order matters when one step needs another’s result

Wordle turn: get guess → check valid → compare letters → show colours. You can’t colour letters before comparing them. Steps that don’t depend on each other, such as updating a turn counter, can move.

From bottom box to sub-procedure

Bottom boxSub-procedureReturns
Place foodplaceFood(grid, snake)a free position
Get keygetKey()a direction
Check crashcheckCrash(snake, gridSize)Boolean
Draw screendrawScreen(grid, snake, food)nothing (procedure)

Why decompose?

  • Each part is small and manageable, so easier to solve.
  • Modules can be tested separately, so errors are easier to find.
  • A team can work on different modules at the same time, so it is finished sooner.
  • Modules can be reused and are easier to maintain.

Watch out for:

  • Drawing a flowchart (with decisions) when asked for a structure diagram.
  • Vague boxes like “Process” or “Do it”.
  • Mixing up decomposition (breaking down) and abstraction (taking detail away).
  • Benefits with no link to the scenario: say who benefits and how.

Quick quiz – marked for you

1. Decomposition is… AO1

Removing detail is abstraction.

2. A hierarchy chart shows… AO1

Structure only – no decisions or loops.

3. “A Boolean variable gameOver” is a component of the… AO2

Variables, lists and subroutines are how it is solved – solution components.

4. “The snake grows when it eats” is a component of the… AO2

It says what must happen, not how.

5. Which is a benefit of decomposition for a team? AO1

So the program is finished sooner.

6. In Wordle, which step must come straight after “get guess”? AO3

Only valid guesses are compared, so checking must come before comparing.

Exam-style questions – mark them yourself

Write your answer, then open Mark your answer. Tick the mark points you hit, read the model answer and use the tips to improve. See the 2.1 exam tips for more help.

AO1[2 marks]

Mabel is writing a game. Explain how decomposition can aid the design of this program.

Mark your answer

Tick each mark point your answer includes.

Model answer: Mabel can split the game into sub-problems such as levels, enemies and lives. Each is simpler to solve and can be designed and tested on its own.

How to improve a weak answer:

  • Say what decomposition does, then why it helps here.
  • “It makes it easier” scores nothing without saying how.
AO2[4 marks]

A school canteen app: students log in with an ID and PIN, choose a meal from the menu and pay. Draw a structure diagram for the app with at least two levels below the top box.

Mark your answer

Tick each mark point your answer includes.

Model answer: Canteen app → Log in (Enter ID, Check PIN), Order (Show menu, Pick meal), Pay (Take payment, Show receipt).

How to improve a weak answer:

  • Use the scenario’s words in every box.
  • No diamonds or loops – this is not a flowchart.
AO2[3 marks]

Identify a sub-procedure needed to place a meal order. Give its name, its parameters and what it returns.

Mark your answer

Tick each mark point your answer includes.

Model answer: placeOrder(studentID, mealID) returns a Boolean: true if the order was placed.

How to improve a weak answer:

  • Give all three parts – name, parameters and return value.
  • Don’t repeat a sub-procedure the question already gave you.

How to revise this

  • Flowcharts and diagrams – draw hierarchy charts for apps you use
  • Teach it – explain decomposition vs abstraction
  • Worked examples – turn bottom boxes into sub-procedures
