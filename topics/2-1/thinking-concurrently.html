2.1.5 Thinking concurrently

Doing more than one thing at once: spotting tasks that can run together, and the benefits and trade-offs of concurrent processing.

Concurrent vs parallel

Concurrent processing: more than one process is in progress at the same time – one starts before another has finished. On one core, each process gets a time slice in turn. Parallel processing: processes run at the same instant on separate cores.

Which parts can run at the same time? (a)

Ask two questions about every task:

  1. Does it need the result of another task? Yes: it must wait (a dependency). No: it can run at the same time.
  2. Does it change data another task uses? Yes: it can still run, but the data must be locked.

Food delivery app: take payment first; then send the order, find a driver and email the receipt at the same time; cooking needs the order; the live map needs the driver; collection needs both.

Benefits and trade-offs (b)

Benefits

  • Faster: independent tasks finish sooner
  • Responsive: the screen keeps working during a long task
  • Many users: a server handles lots of requests at once
  • Less idle time: one task runs while another waits for a file or the network

Trade-offs

  • Not everything splits: some tasks must wait
  • Not n times faster: splitting and combining take time
  • Shared data can be corrupted, so record locking is needed
  • Harder to write, test and debug: bugs depend on timing

When tasks collide

A balance is £100. Task A pays in £50; task B takes out £30. In the order A1 read, B1 read, A2 write, B2 write:

StepTask ATask BBalance
A1reads 100100
B1reads 100100
A2writes 150150
B2writes 7070

It should be £120: A’s £50 is lost. Record locking stops a second process changing a record that is in use.

Beyond the spec – Amdahl’s law: a 100 s job with 20 s that can’t be split takes 25 s on 16 cores and never less than 20 s, however many cores you add.

Watch out for:

  • “It does two things at once” and nothing more.
  • “It is faster” with no context – faster than what, for whom?
  • Only giving benefits when the question says “discuss”.
  • Claiming 4 cores is always 4 times faster.

Quick quiz – marked for you

1. Which is true? AO1

Parallel is one kind of concurrent. Concurrency on one core uses time slices.

2. Which pair of tasks can run at the same time? AO2

Neither page needs the other. The others each need the result of the first step.

3. One core runs 3 programs by… AO1

Each program gets a slice of processor time in turn.

4. Going from 1 core to 4 cores makes a program… AO3

Some parts can’t be split, and the cores must coordinate.

5. Two tasks change the same record at once. What can happen? AO2

One overwrites the other, unless the record is locked.

6. A balance is £100. A reads, B reads, A writes +£50, B writes −£30. What is the final balance in £? AO2

B wrote 100 − 30 over A’s 150. It should be £120.

Exam-style questions – mark them yourself

Write your answer, then open Mark your answer. Tick the mark points you hit, read the model answer and use the tips to improve. See the 2.1 exam tips for more help.

AO1[2 marks]

Describe what is meant by the term concurrent processing. (October 2021)

Mark your answer

Tick each mark point your answer includes.

Model answer: Concurrent processing is when more than one process is in progress at the same time, with one starting before another has finished. On one processor each gets a slice of processor time in turn.

How to improve a weak answer:

  • “Two things at once” alone is one mark at most – add how it works.
  • Mention time slices or multiple processors.
AO2[3 marks]

An online circus game. Explain why concurrent processing is needed to allow multiple users to log in and interact with game elements at the same time. (October 2021)

Mark your answer

Tick each mark point your answer includes.

Model answer: Many users will send requests to the server at the same time, and each needs a reply in a reasonable time. With concurrent processing the server can deal with other requests while one is waiting, so one user doesn’t slow down everyone else.

How to improve a weak answer:

  • Explain = a point, then why it matters in this scenario.
  • Don’t just say “faster” – faster for whom?
AO3[4 marks]

A streaming app downloads the next part of a film while the current part plays. Explain one benefit and one trade-off of using concurrent processing in this app.

Mark your answer

Tick each mark point your answer includes.

Model answer: Benefit: the film keeps playing while the next part downloads, so the viewer doesn’t have to wait for it to buffer. Trade-off: the next part must be stored in memory while the current part plays, so the app needs more memory, and it is harder to program because the two tasks must stay in step.

How to improve a weak answer:

  • Point + expansion, twice.
  • Link both sides to the streaming app.

How to revise this

  • Comparison tables – concurrent vs parallel; benefits vs trade-offs
  • Flowcharts and diagrams – draw dependency charts for everyday tasks
  • Planning extended answers – the 9-mark “discuss” question

These are the best fit for this part of the topic, but you can use any revision technique that works for you.
