Decision points (a)

A decision point is where the program checks a condition and chooses what to do next. They appear in selection (if, switch) and iteration (while, for, until).

01 tries = 0
02 pw = input("Password: ")
03 while pw != stored AND tries < 2
04     tries = tries + 1
05     pw = input("Try again: ")
06 endwhile
07 if pw == stored then
08     print("Welcome")
09 else
10     print("Account locked")
11 endif

Line 03 (loop): is the password wrong AND have fewer than 2 retries been used? True: lines 04–05, then check again. False: jump to line 07.

Line 07 (selection): does the password match? True: “Welcome”. False: “Account locked”.

Describe every decision as: where, what is checked, what happens if True and if False.

  • De Morgan: NOT (a > 5 AND b > 5) is a <= 5 OR b <= 5 (links to 1.4.3).

How decisions affect flow (c)

Trace tables show the effect: one column per variable, a new row each pass, output in its own column. Never skip a pass of the loop.

n = 5
for count = 1 to n
    a = n - count
    b = 3 * a + count
next count
print(b)

Watch out for:

  • Describing only what happens when the condition is True – the False path earns marks too.
  • Naming the construct (“an IF statement”) instead of what it checks.
  • > vs >=: “at least” and “over” are different.
  • Using OR where both must be true, so the condition is always True.

Quick quiz – marked for you

1. A ride needs riders to be at least 120 cm. Which condition? AO2

“At least” includes 120, so >=.

2. Free delivery for orders over £50, or for anyone who is a member. AO2

“Over” means >, and either reason is enough, so OR.

3. A valid mark is from 0 to 100 inclusive. AO2

B is always True – it would accept 250.

4. Which is the same as NOT (a > 5 AND b > 5)? AO3

De Morgan: NOT (P AND Q) = NOT P OR NOT Q, and NOT (a > 5) is a <= 5.

5. In the trace table above (n = 5), what is the value of b when count = 3? AO2

a = 5 − 3 = 2, so b = 3 × 2 + 3 = 9.

6. Keep asking until the guess is correct or 3 guesses have been used: while ___ AO3

Keep looping only while BOTH are true. B keeps going after 3 wrong guesses; D allows a fourth.

AO2[4 marks]

A board game: logical conditions are checked once a player has rolled the dice. Describe two different logical conditions and how the result will affect the outcome of the game. (June 2024)

Mark your answer

Tick each mark point your answer includes.

Model answer: Has the player landed on square 100? If so, they are announced as the winner. Has the timer reached 0? If so, the game is declared a draw.

How to improve a weak answer:

  • Each condition must be a yes/no question – “check the dice” isn’t.
  • The outcome must follow from that condition: “1 mark for condition and 1 mark for outcome”.
AO2[4 marks]

Trace this program for the inputs 4, −2, 6, −1. State the output.

01 total = 0
02 count = 0
03 num = int(input("Number: "))
04 while num != -1
05     if num > 0 then
06         total = total + num
07         count = count + 1
08     endif
09     num = int(input("Number: "))
10 endwhile
11 print(total / count)
Mark your answer

Tick each mark point your answer includes.

Model answer: num 4 → total 4, count 1. num −2 → skipped. num 6 → total 10, count 2. num −1 → loop ends. Output: 10 / 2 = 5.

How to improve a weak answer:

  • One row per pass – most lost marks come from a missed row.
  • −2 still goes into num, even though it isn’t added.
AO3[3 marks]

For the same program, which inputs make line 11 crash? Explain a fix.

Mark your answer

Tick each mark point your answer includes.

Model answer: If the first input is −1 (or no positive numbers are entered), count is still 0, so line 11 divides by zero and crashes. Add if count > 0 then before the division and otherwise print “No numbers”.

How to improve a weak answer:

  • Name the input, the reason and the fix – three marks, three parts.
  • Write the fix as a condition, not just “add validation”.

How to revise this

  • Trace tables – trace loops and selection by hand
  • Flowcharts – turn code into a flowchart to see each decision
  • Worked examples – turn words into conditions

These are the best fit for this part of the topic, but you can use any revision technique that works for you.
