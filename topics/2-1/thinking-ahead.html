Inputs, outputs and preconditions (a, b)

Inputs and outputs

  • Input: data the solution must receive – membership ID, date of the class.
  • Output: data or an action it produces – seat numbers, an emailed ticket, “Not enough seats”.
  • Look for hidden inputs: a car park charge needs the entry and exit times from the clock.
  • Use the scenario’s words, not “the information”.

Preconditions

SubroutinePrecondition
binarySearch(list, item)the list is sorted
findMax(list)at least one item
divide(a, b)b ≠ 0
pop()the stack is not empty
getItem(index)0 ≤ index < length
dijkstra(graph)no negative weights

Why specify preconditions? The subroutine can be reused safely without reading its code; the programmer knows which checks to make before calling it, so there are no unnecessary checks; shorter code is easier to debug.

Caching (c)

Caching is the temporary storage of data that has been used, in a location that is faster to access, in case it is needed again. It is thinking ahead: the system predicts what you will need.

Benefits

  • Faster access to data used again
  • Less bandwidth used, which saves cost
  • Less load on servers

Drawbacks

  • Stale data: the copy may be out of date
  • A miss is slower, as the cache is checked first
  • Uses extra memory
  • Complex to decide what to keep

Where? CPU cache (1.1.1), browser cache (1.3.4), DNS cache (1.3.3), proxy servers and CDNs. Memoisation caches function results: a recursive fib(40) makes 331,160,281 calls; with a cache it makes 79.

Reusable program components (d)

A reusable component is code written and tested once that can be used many times: subroutines, classes and libraries.

Benefits

  • Saves the programmer time: written once, used many times
  • Already tested, so fewer errors
  • Fix a bug in one place
  • Work can be shared between programmers

Drawbacks

  • Take longer to design so they work in every case
  • Must be fully documented
  • A change to a shared library can break programs that use it

Hard to reuse

price = 50
def addVAT():
    global price
    price = price * 1.2
    print("Total: £" + str(price))

Global variable, fixed VAT rate, prints instead of returning, no documentation.

Reusable

def addVAT(price, rate):
    # Returns price with VAT added
    # Precondition: price >= 0
    return price * (1 + rate)

total = addVAT(50, 0.2)

Parameters in, return value out, documented.

Watch out for:

  • Listing processes (“calculate the cost”) as inputs or outputs – they must be data.
  • Vague inputs like “the user’s details” – name them from the scenario.
  • Caching answers that say “it uses the cache” but not what is stored.
  • Saying reusable code saves “time” without saying whose: the programmer’s.

Quick quiz – marked for you

1. Which is an input to a thermostat program? AO2

Switching on is an output (a result). The temperature is data going in.

2. What is the precondition for a binary search? AO1

Binary search halves a sorted list. On unsorted data it gives wrong results.

3. findMax(list) starts with max = list[0]. Which precondition is needed? AO2

An empty list has no item at index 0, so the program crashes.

4. Should a live football score be cached? AO3

Data that changes often or must be current (scores, bank balances) shouldn’t be cached for long.

5. A cache miss means… AO1

A hit finds it; a miss fetches it and usually stores a copy.

6. Which is a drawback of reusable components? AO1

The others are benefits.

AO2[4 marks]

A cinema booking program: customers enter the film, showing time and number of tickets. If seats are free it shows the seat numbers and cost and emails a ticket; if not, it shows “Not enough seats”. Identify two inputs and two outputs.

Mark your answer

Tick each mark point your answer includes.

Model answer: Inputs: the film and the number of tickets. Outputs: the seat numbers and the emailed ticket.

How to improve a weak answer:

  • Copy the scenario’s words exactly.
  • Outputs are data or actions, not processes like “checks the seats”.
AO1[3 marks]

Explain why the programmer should create reusable components for the cinema program.

Mark your answer

Tick each mark point your answer includes.

Model answer: A component such as calculateCost is written once and used many times, which saves the programmer time. It has already been tested, so there are fewer errors, and if a bug is found it only needs fixing in one place.

How to improve a weak answer:

  • One mark per point, so make three separate points.
  • Name a component from the scenario to show application.
AO3[4 marks]

(a) Describe how caching could be used in the cinema program. [2] (b) Explain one drawback of caching here. [2]

Mark your answer

Tick each mark point your answer includes.

Model answer: (a) Data that has been used, such as the film listings, is stored in the cache so it can be accessed quickly when the next customer asks for it. (b) The cached seat plan could be out of date, so a customer might be offered a seat someone else has just booked.

How to improve a weak answer:

  • Say what is stored – named from the scenario – and why.
  • Drawback: what goes wrong, then what it means for the user.

How to revise this

  • Worked examples – list inputs, outputs and preconditions for new scenarios
  • Comparison tables – benefits vs drawbacks of caching and reuse
  • Flowcharts – draw the cache hit / miss process from memory

These are the best fit for this part of the topic, but you can use any revision technique that works for you.
