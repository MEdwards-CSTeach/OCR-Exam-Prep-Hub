Revision technique

Condensing notes

Shrink your notes in stages until a few key words are enough to bring it all back.

At a glance

  • Time: 20–40 minutes
  • Best for: Wordy topics and lesson notes
  • You need: Lesson slides, notes, index cards

Why it works

Deciding what to keep and what to cut makes you think hard about what really matters. Each time you shrink your notes you go over the content again, and the final key words act as a trigger for everything you learned.

How to do it

  1. Cornell notes: split a page into a narrow cue column, a wide notes column and a summary box at the bottom.
  2. Write notes in the right-hand column from your lesson slides.
  3. Write questions in the cue column that the notes answer.
  4. Summarise the whole page in two or three sentences at the bottom.
  5. Shrink it: page → bullet points → index card → three key words. Can you rebuild the page from the key words?

Best topics for this technique

  • 1.2.3 Software development methodologies
  • 1.3.1 Compression, encryption and hashing
  • 1.3.4 Web technologies
  • 1.5.1 Computing legislation
  • 1.5.2 Moral and ethical issues

These topics suit this technique well, but you can use it for any topic.

Tip: Start from your lesson slides, not a textbook. They match what you were taught and the spec wording.

Examples

Example 1

Cornell notes: symmetric and asymmetric encryption

1.3.1

Cover the notes column and use the cue questions to test yourself.

Cue questions

  • What is symmetric encryption?
  • What is its main problem?
  • What is asymmetric encryption?
  • Which key encrypts a message to me?
  • How are both used together?

Notes

  • Symmetric: the same key encrypts and decrypts. Fast.
  • The key must be shared. If it is intercepted, every message can be read (the key exchange problem).
  • Asymmetric: two linked keys – a public key anyone can have and a private key kept secret.
  • Sender encrypts with the receiver’s public key. Only the receiver’s private key can decrypt it.
  • Asymmetric is slower, so it is often used to share a symmetric key safely. The symmetric key then encrypts the data (e.g. HTTPS).

Summary

Symmetric uses one shared key: fast, but sharing the key is risky. Asymmetric uses a public/private pair: solves key sharing but is slower. Real systems use both.

Example 2

Shrink it: the waterfall lifecycle

1.2.3

The same content at four sizes. Each level is about half the size of the one before.

Level 1 – full notes

The waterfall lifecycle is a software development model where each stage – requirements, design, implementation, testing, deployment and maintenance – is completed in order before the next starts. Each stage is signed off, and it is hard to go back to an earlier stage. The user is mainly involved at the start and the end. It suits large projects with clear, fixed requirements, but late changes are costly and problems may not be found until testing.

Level 2 – bullet points

  • Stages in order: requirements → design → implementation → testing → deployment → maintenance
  • Each stage signed off; hard to go back
  • User involved at start and end only
  • ✓ Clear structure; suits large projects with fixed requirements
  • ✗ Late changes are costly; problems found late

Level 3 – index card

Waterfall = linear stages, signed off · user at start/end · ✓ fixed requirements, big projects · ✗ late changes costly

Level 4 – key words

Linear · Fixed · Late
