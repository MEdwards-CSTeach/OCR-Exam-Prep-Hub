Revision technique

Teach it (the Feynman technique)

Explain a topic in simple words, as if to someone younger. Where you get stuck is what you need to revise.

At a glance

  • Time: 10–15 minutes
  • Best for: Tricky concepts and “explain” questions
  • You need: A friend, family member – or a rubber duck

Why it works

If you can’t explain something simply, you don’t fully understand it yet. Explaining out loud finds the gaps that rereading hides. It also practises “explain” questions, which need clear reasons, not just facts.

How to do it

  1. Pick one concept, e.g. recursion.
  2. Explain it in plain words as if to a Year 7 student – out loud or written down.
  3. Spot where you got stuck or used a word you couldn’t explain. That is your gap.
  4. Go back to your notes to fill the gap.
  5. Explain it again, more simply, and add an analogy or example.

Best topics for this technique

  • 1.2.1 Paging, segmentation, virtual memory
  • 1.2.4 Object-oriented programming
  • 1.3.1 Hashing and encryption
  • 2.1.1 Abstraction
  • 2.2.1 Recursion, passing by value and reference
  • 2.3.1 How each algorithm works

These topics suit this technique well, but you can use it for any topic.

Tip: Record yourself on your phone. Listening back is a good way to hear where your explanation was vague.

Examples

Example 1

Recursion

2.2.1

First try: “Recursion is when a function calls itself.”

Gaps found: When does it stop? What happens in memory? Why not just use a loop?

Better explanation: “A recursive function solves a problem by calling itself on a smaller version of the same problem. It needs a base case – a simple case it can answer without calling itself – or it would never stop. Each call goes on the call stack with its own variables and return address. When the base case is reached, the calls return one by one. Too many calls cause a stack overflow, and recursion usually uses more memory than a loop.”

Analogy: Russian dolls – open each doll (call) until you reach the smallest one (base case), then put them back together (return).

function factorial(n)
    if n == 0 then
        return 1                     // base case
    else
        return n * factorial(n - 1)  // recursive call on a smaller problem
    endif
endfunction
Example 2

Hashing

1.3.1 + 1.4.2

First try: “Hashing scrambles a password so hackers can’t read it.”

Gaps found: That sounds like encryption – what is the difference? What else is hashing used for?

Better explanation: “A hash function turns any input into a fixed-size value called a hash. It is one-way – unlike encryption, you can’t get the input back. The same input always gives the same hash. Websites store the hash of your password and compare hashes when you log in. Hash tables use a hash to work out where to store or find data, so look-ups are very fast. If two inputs give the same hash, that is a collision.”

Analogy: a fingerprint – it identifies the person, but you can’t rebuild the person from it.

Self-check: did your explanation use these words correctly? fixed size · one-way · same input, same hash · hash table · collision
