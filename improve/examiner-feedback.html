Exam tips and improving your grade

OCR A Level Computer Science • H446

Examiner feedback by topic

What OCR examiners say students get wrong, topic by topic, taken from the published examiners’ reports. Use it to check your notes and your practice answers.

How to use this page

  1. Find your topic in the tables.
  2. Read what examiners saw.
  3. Check your notes and answers for the same mistake.
  4. Practise the “do this instead”.

Mistakes that come up in every topic

The same six problems appear in almost every examiners’ report, on both papers.

Vague, unqualified words

Seen: “Faster”, “easier”, “saves time”, “efficiency” on their own score nothing.

Fix: Say faster at what, and why. Whose time is saved?

Not using the scenario

Seen: “Many candidates lost marks through not contextualising their responses.” (P1 2020, 2021)

Fix: Name things from the question in every point.

Re-using the question

Seen: Giving examples or terms the question already gave, or repeating the stem back.

Fix: If it is in the question, it is not the answer.

One side only

Seen: Compare questions answered for one thing; extended answers with no balance.

Fix: Use “whereas”. Give both sides, then a judgement.

Naming, not explaining

Seen: Features and terms listed with no description or expansion.

Fix: Name it, then say what it does or why it matters.

Brand names and loose terms

Seen: OS and software brand names; “vertices” for nodes; “autocorrect” for auto-complete.

Fix: Use the exact technical term.

1.1 Processors, input, output and storage

Paper 1. Most marks are lost by mixing up similar parts.

TopicWhat examiners sawDo this insteadReport
1.1.1 RegistersSaying a register fetches or passes data. “A register is a temporary store for data/instructions/addresses and as such doesn’t fetch or pass anything.”

Say what each register holds; the buses and control unit move things.

For example: State the purpose of the MAR. [1]

Weak It fetches the address of the next instruction.

Better It holds the address of the memory location that is about to be read from or written to.

P1 2024
1.1.1 FDE cycleNaming a register that is used in a different stage from the one asked about.

Learn which registers are used in fetch, decode and execute separately.

For example: Name one register used in the decode stage and describe its role. [2]

Weak The PC – it holds the address of the next instruction. (The PC is used in the fetch stage.)

Better The CIR (1). It holds the instruction that has just been fetched, ready for the control unit to decode it (1).

P1 2024
1.1.1 PipeliningConfusing pipelining with threading or multiple cores; bringing in multiple cores when the question was about pipelining.

Pipelining = one core overlaps the stages of different instructions.

For example: Explain how pipelining improves processor performance. [2]

Weak More cores can work on instructions at the same time.

Better While one instruction is executed, the next is decoded and the one after is fetched (1), so the processor is not idle and more instructions are completed in the same time (1).

P1 2021, P1 2024
1.1.2 Multi-core and parallel systems“A processor with multiple cores” is not a definition.

Define a core, then apply it.

For example: Explain why a quad-core processor could run a game more quickly. [2]

Weak Because it is a processor with multiple cores.

Better Each core is an independent processing unit that can fetch, decode and execute on its own (1), so different parts of the game, such as physics and sound, can be processed at the same time (1).

P1 2019
1.1.1 / 1.1.3 Memory, cache and storage (RAM, ROM, cache, virtual and cloud storage)Confusing primary with secondary storage, RAM with cache, and virtual storage with virtual memory. Not realising cloud storage is still on a physical medium. ROM described, but with no different use given.

Know each term’s exact job, and answer the use the question asks for.

For example: Explain why a computer has cache as well as RAM. [2]

Weak Cache stores the programs that are currently running. (That is RAM.)

Better Cache is a small amount of very fast memory on or next to the processor (1). It holds frequently used instructions and data, so the processor doesn’t have to wait for slower RAM (1).

P1 2023, P1 2024
1.1.3 Input and output devices (and devices for embedded systems)Generic uses not linked to the scenario, e.g. “Speaker – to output the response” (an output device). Input devices that couldn’t fit in an embedded system, such as a fitness tracker.

Pick a device that suits the scenario and say what it does in that scenario.

For example: A smart speaker answers spoken questions. Identify one output device and explain why it is needed. [2]

Weak Speaker – to output the response.

Better A speaker (1), so the answer to the user’s spoken question can be read out loud, as the device has no screen (1).

1.2 Software and software development

Paper 1. Answers are often true but too vague, or describe the wrong thing.

TopicWhat examiners sawDo this insteadReport
1.2.1 Operating system rolesNaming roles without describing them; describing scheduling and interrupts when the question had already given them.

Never re-use examples from the question. Name + describe for each mark.

For example: The OS handles scheduling and interrupts. Describe two other roles of an operating system. [4]

Weak Interrupts and memory management. (Interrupts was in the question, and neither role is described: 1 mark at most.)

Better Memory management (1): it allocates RAM to each program and stops one program overwriting another’s memory (1). File management (1): it lets users save, name and organise files in folders (1).

P1 2024
1.2.1 Scheduling algorithmsConfusing shortest remaining time with shortest job first; bringing priorities and interrupts into first come first served.

Learn one sentence that separates each algorithm.

For example: Explain the difference between shortest job first and shortest remaining time. [2]

Weak SJF runs the shortest job and SRT runs the job with the shortest time.

Better SJF runs the job with the shortest total time and does not stop it once it starts (1). SRT is pre-emptive: if a new job arrives with less time left than the current one, it switches to the new job (1).

P1 2019, P1 2024
1.2.1 InterruptsSaying interrupts are dealt with “during an FDE cycle”, or immediately, with no mention of priorities.

Interrupts are checked at the end of each FDE cycle and handled by priority.

For example: Describe how the processor deals with an interrupt. [3]

Weak It stops what it is doing straight away and deals with the interrupt.

Better At the end of each FDE cycle the processor checks for interrupts (1). If the interrupt has a higher priority than the current task, the register contents are saved on a stack and the interrupt service routine runs (1). The saved values are then restored and the task carries on (1).

P1 2023
1.2.1 Memory management: virtual memory, paging and segmentationKnowing pages are fixed size and segments variable, but not linking either to virtual memory.

Explain that pages are what get moved between RAM and virtual memory.

For example: Explain how paging is used with virtual memory. [2]

Weak Pages are fixed size and segments are variable size.

Better When RAM is full, pages of a program that are not currently needed are moved to virtual memory on secondary storage (1), and swapped back into RAM when they are needed again (1).

P1 2023
1.2.1 Types of OS, device drivers and virtual machinesBrand names as an OS type; drivers described as working with “the computer”; describing a virtual machine instead of why you would use one.

Use general terms (embedded, real-time, distributed). Answer the “why”.

For example: Explain why a software company might use virtual machines. [2]

Weak A virtual machine is software that pretends to be a computer. (A description, not a reason.)

Better To test new software on several operating systems using one physical computer (1), so untested code can’t damage the real system and no extra hardware is needed (1).

P1 2019, P1 2023
1.2.2 Applications, utilities and open sourceBrand names (no marks); utility software given as business application software; “email” as the software for writing letters; open source described with no drawback of closed source.

Use the general type of software, and answer every part of the question.

For example: Identify the type of application software a business should use to write letters to customers. [1]

Weak Microsoft Word. (A brand name.) Or: email.

Better A word processor.

P1 2023, P1 2024
1.2.2 Translators, linkers and loadersConfusing an assembler with a compiler or interpreter; few said a linker forms a single executable; loaders confused with compilers and IDEs.

Linker: joins code and libraries into one executable. Loader: copies it into memory to run.

For example: Describe the role of a linker. [2]

Weak It links the code with libraries.

Better It combines the compiled object code with the code of any library routines it uses (1) into a single executable file (1).

P1 2024
1.2.4 Assembly language and addressing modes“Easier to read” for assembly; giving “by reference or value” as addressing modes; descriptions that “lacked clarity”; giving a mode the question already named.

Learn immediate, direct, indirect and indexed: what the operand means in each.

For example: Describe indirect addressing. [2]

Weak It finds the address indirectly.

Better The operand holds the address of a memory location (1), and that location holds the address where the data is found (1).

1.3 Exchanging data

Paper 1. Databases and networks: precise terms decide the marks.

TopicWhat examiners sawDo this insteadReport
1.3.1 Encryption and hashingWriting about hash tables when the question was about hashing to secure data; knowing the theory but not applying it.

Hashing for security is one-way. Apply it to the data in the scenario.

For example: Explain how hashing keeps customers’ passwords secure. [2]

Weak The passwords are put in a hash table so they can be found quickly.

Better Each password is put through a one-way hash function and only the hash is stored (1). At login the entered password is hashed and compared with the stored hash, so a stolen database doesn’t reveal the passwords (1).

P1 2023
1.3.2 Relational databases and keysConfusing a database with a table (“a number of related databases”); “A foreign key links two databases and not 2 tables/entities”; mixing up the keys.

A relational database is a set of related tables; a foreign key links tables.

For example: Define the term foreign key. [2]

Weak A key that links two databases.

Better A field in one table that is the primary key of another table (1), used to link the two tables (1).

P1 2020, P1 2024
1.3.2 Referential integrity, ACID and normalisationNot explaining referential integrity; confusing atomicity in ACID with referential integrity; thinking deleting a review deletes the user; wrong idea of “atomic” data.

Referential integrity: every foreign key value must match an existing primary key.

For example: Explain referential integrity, using the User and Review tables. [2]

Weak It makes sure the data is correct.

Better Every UserID in the Review table must match a UserID that exists in the User table (1), so a review can never point to a user who doesn’t exist (1).

P1 2019, P1 2020
1.3.2 SQLGetting the WHERE right but missing the DELETE statement.

Write the whole statement, not just the condition.

For example: Write SQL to remove every film with a rating below 2 from the table Film. [2]

Weak WHERE Rating < 2

Better DELETE FROM Film WHERE Rating < 2;

P1 2023
1.3.3 Networks, protocols, layering and hardwareLAN benefits given when advantages to the business were asked; defining a protocol but not explaining it; naming TCP/IP layers when asked for protocols; not saying why protocols are layered; “connects devices” for every piece of hardware.

Use protocol names (HTTP, TCP, IP). Each device needs its own specific job.

For example: Describe the role of a router. [2]

Weak It connects devices.

Better It forwards packets between different networks (1), using the destination IP address to choose the route (1).

P1 2023, P1 2024
1.3.4 Web technologies: search engines, client- and server-side, CSSConfusing search engine indexing with typing a URL; saying JavaScript form checks run “server side”; CSS with quotes instead of colons.

Indexing = crawlers build an index before you search. Practise exact CSS syntax.

For example: JavaScript checks the surname box isn’t empty. Is this client-side or server-side processing? Explain. [2]

Weak Server-side, because it is checking the data.

Better Client-side (1): the JavaScript runs in the user’s browser, so the error appears at once without sending anything to the server (1).

1.4 Data types, data structures and Boolean algebra

Both papers. Careless method and confusing similar structures.

TopicWhat examiners sawDo this insteadReport
1.4.1 Binary, hex, negative numbers and subtractionMissing or adding an extra zero; answering in binary when denary was asked for; confusing sign and magnitude with two’s complement; no working in subtraction.

Check the bit count and the method asked for. Always show the working.

For example: Convert −45 to 8-bit two’s complement. [2]

Weak 10101101 (That is sign and magnitude.)

Better 45 = 00101101. Flip the bits: 11010010. Add 1: 11010011.

P1 2019, P1 2024
1.4.1 Floating pointMantissa not written to the right number of bits; can’t convert back to denary; precision and range answers the wrong way round.

More mantissa bits = precision. More exponent bits = range.

For example: Explain the effect of using more bits for the mantissa and fewer for the exponent. [2]

Weak It increases the range but makes it less accurate. (Backwards.)

Better Precision increases, because more significant bits are stored (1), but the range decreases, because the exponent is smaller (1).

P1 2019, P1 2023, P1 2024
1.4.2 Arrays and recordstowns = [ ] with no size; using an array for mixed data types; vague array properties; records confused with database records.

Declare arrays with their size. An array holds one data type; a record groups fields of different types.

For example: Declare an array to hold the names of 20 towns. [2]

Weak towns = [ ]

Better array towns[20]

P1 2019, P1 2024, P2 2022, P2 2024
1.4.2 Lists and linked listsData written in the pointer column; a list confused with a linked list; describing pointers instead of how to reach an item.

Follow the pointers from the head, step by step.

For example: Describe how to find the second item in a linked list. [2]

Weak A linked list has data and pointers.

Better Start at the node the head pointer points to (1), then follow that node’s pointer to the next node, which is the second item (1).

P1 2023, P1 2024, P2 2023
1.4.2 Stacks and queues (including circular and priority queues)Pop steps in the wrong order; pointer left on the last item, not the next free space; len(numbers) instead of the stack pointer; shifting every item in a circular queue; push/pop used for queues.

Use the pointers you are given. Check, then copy and move the pointer in the right order.

For example: Describe the steps to pop an item from a stack, where top points to the top item. [3]

Weak Take the item off the top.

Better Check the stack is not empty (1). Copy the item at position top (1). Take 1 off top and return the copied item (1). (If the pointer holds the next free space, take 1 off first, then copy.)

P1 2023, P2 2022, P2 2024
1.4.2 Trees, binary search trees and graphsBinary trees confused with general trees; “trees have at most two children”; directed confused with weighted; BST search confused with traversal.

Only binary trees limit nodes to two children. A BST is ordered: left smaller, right larger.

For example: State one difference between a tree and a graph. [1]

Weak A tree can only have two children per node.

Better A tree has a root and no cycles, whereas a graph can contain cycles.

P2 2022, P2 2023, P2 2024
1.4.3 Logic gates and Boolean expressionsDrawing a flowchart instead of a logic circuit; confusing AND and OR; wrong use of NOT, e.g. ¬(A ∨ B).

Use the gate symbols. Check your expression with one row of the truth table.

For example: The alarm (Q) sounds when the door is open (D) and the system is armed (S). Write the Boolean expression. [1]

Weak Q = D ∨ S (This sounds whenever the door is open.)

Better Q = D ∧ S

P1 2023, P1 2024
1.4.3 Karnaugh maps and Boolean lawsGroups that include zeros; missing the wrap-around group; an extra group for a row already covered; OR used instead of AND when distributing.

Group 1s only, in sizes 1, 2, 4 or 8, as large as possible. Groups can wrap round the edges.

For example: Simplify the K-map. [3]

Weak Three separate pairs, one of which covers a 0, and the two 1s on opposite edges left in their own groups.

Better The fewest, largest groups of 1s only – including a group that wraps from the left edge to the right – then one term per group.

1.5 Legal, moral, cultural and ethical issues

Paper 1 extended answers. Balance and accuracy.

TopicWhat examiners sawDo this insteadReport
1.5.1 Legislation (including copyright)Not giving the full name of the Act; thinking you can use copyright images “just by crediting the artist”; not naming the powers an Act gives.

Learn each Act’s full name and two things it allows or forbids.

For example: A business wants to use a photo it found online in an advert. Explain whether it can. [2]

Weak Yes, as long as it credits the photographer.

Better Not without permission: the photo is protected by the Copyright, Designs and Patents Act 1988 (1), so the business needs the copyright holder’s permission or a licence to use it (1).

P1 2023, P1 2024
1.5.2 Moral, cultural, ethical and environmental issuesOne-sided answers; few positive impacts; drifting to other countries or to accessibility when asked about cultures.

Give both sides, stay on the question, finish with a judgement.

For example: Discuss the environmental impact of large data centres. [9]

Weak Only negatives: they use huge amounts of electricity and create e-waste.

Better Negatives (electricity, cooling water, e-waste) and positives (many organisations share efficient servers instead of running their own; some data centres use renewable energy), then a judgement: on balance the impact depends on how the centre is powered.

2.1 Computational thinking and 2.2.2 computational methods

Paper 2. Definitions are too general and not applied to the scenario.

TopicWhat examiners sawDo this insteadReport
2.1.1 Thinking abstractly“Simplifying a problem” with no how; examples like “terrain” without saying how it differs from reality; graphics examples for a text-based game; restating the definition as a reason; only one example when two were asked.

Say which detail is removed and why, from this scenario. Give distinct reasons.

For example: A text-based adventure game. Give one example of abstraction in the game. [2]

Weak The graphics are simplified. (The game has no graphics.)

Better Each room is stored as just a name and a text description (1). Real details such as its size or furniture are left out, because the player only needs to know where they can go next (1).

P2 2022, P2 2023, P2 2024
2.1.2 Thinking ahead: inputs, outputs and cachingGiving input/output devices instead of data; unqualified answers like “left arrow key”; describing caching or giving an example, rarely both.

Inputs and outputs are data in the scenario. Caching: what is stored + why.

For example: Identify two inputs to a cinema ticket booking program. [2]

Weak Keyboard and mouse.

Better The number of tickets wanted (1). The film and showing time chosen (1).

P2 2022, P2 2023, P2 2024
2.1.3 Thinking procedurally: decompositionNot saying the problem is broken into sub-problems; benefits with no expansion; answering for the wrong part of the scenario (creating accounts instead of logging in).

Definition: break into sub-problems. Benefit: point + why it helps here.

For example: Describe what is meant by decomposition. [2]

Weak Making the problem simpler.

Better Breaking a problem down into smaller sub-problems (1) until each is small enough to be solved on its own, e.g. as one subroutine (1).

P2 2023, P2 2024
2.1.5 Thinking concurrentlyConfusing parallel with concurrent; “many things at the same time” without naming them; linking pipelining to concurrency. “Concurrent processing does not increase the actual speed of the CPU.”

Name the tasks from the scenario. The benefit is more done in the same time, not a faster CPU.

For example: Give one benefit of concurrent processing for a ticket-selling website. [2]

Weak It makes the CPU faster.

Better Many customers’ requests can be in progress at once (1), so one customer waiting for a payment doesn’t hold up everyone else (1).

P2 2023
2.2.2 Computational methods: data mining, performance modellingFew evaluated data mining; stress testing and performance modelling confused with ordinary testing.

Evaluate: benefit, drawback, judgement. Performance modelling = predicting behaviour under growing load.

For example: Describe what is meant by performance modelling. [2]

Weak Testing the program to find bugs.

Better Using a model or simulation to predict how the system will behave under different loads (1), such as 10,000 users at once, without testing it on the real system (1).

2.2.1 Programming techniques

Paper 2. Code that is nearly right, and terms named but not explained.

TopicWhat examiners sawDo this insteadReport
2.2.1 (a) Loops and selectionPre- and post-condition loops not distinguished; off-by-one errors; uninitialised counters; a return inside the loop; “actions” given when asked for a decision.

Trace your loop with the first and last values. A decision has a True/False condition and two outcomes.

For example: Explain the difference between a while loop and a do … until loop. [2]

Weak A while loop repeats while something is true.

Better A while loop checks its condition at the start, so its code may never run (1). A do … until loop checks at the end, so its code always runs at least once (1).

P2 2022, P2 2024
2.2.1 (c, d) Variables, scope and parameters“By value can’t change the value while by reference can” with no local copy or memory address; vague variable definitions; thinking a local and a global variable can’t share a name.

By value: a copy. By reference: the address of the original. A local variable takes precedence.

For example: Explain the difference between passing a parameter by value and by reference. [2]

Weak By value can’t change the value, but by reference can.

Better By value passes a copy, so changes inside the subroutine don’t affect the original (1). By reference passes the address of the original, so changes inside the subroutine do change it (1).

P2 2022, P2 2024
2.2.1 (d, e) Functions, procedures, IDEs and reuse“It has an output” to describe a function; IDE features named, not explained (and “autocorrect” for auto-complete); unqualified “saves time”.

A function returns a value. Name the IDE feature and say how it helps.

For example: Describe how breakpoints help a programmer to debug code. [2]

Weak Breakpoints help find errors.

Better A breakpoint pauses the program at a chosen line (1), so the programmer can inspect the values of variables at that point and find where it goes wrong (1).

P2 2022, P2 2023, P2 2024
2.2.1 (b) RecursionOnly “calls itself” with no base case; struggling to unwind calls; giving “10” instead of the call calculate(10); using / when integer division was needed.

Two features: calls itself + base case. Trace down, then fill the returns back up.

For example: Give the function call that would return 55. [1]

Weak 10

Better calculate(10)

P2 2022, P2 2023
2.2.1 (f) Object-oriented programming (also 1.2.4)Class declaration confused with the constructor; private getters; passing a parameter into a getter; using attributes directly instead of methods; strings instead of Booleans; “all queues inherit” when only objects were needed.

Constructors set attributes from parameters. Getters are public functions with no parameter. Use the methods given.

For example: Write a getter method for the private attribute name. [2]

Weak private function getName(name) return name endfunction

Better public function getName() return name endfunction

2.3 Algorithms

Paper 2. Know the steps exactly and show them on the data given.

TopicWhat examiners sawDo this insteadReport
2.3.1 Searching: linear and binary“Must be sorted” or “organised” without saying what; linear search steps missing the comparison with the target.

Binary search: the list must be sorted. Linear: compare each item with the target in turn.

For example: State a precondition for a binary search. [1]

Weak The data must be organised.

Better The list must be sorted into order, e.g. ascending, by the value being searched for.

P2 2022, P2 2024
2.3.1 Sorting: bubble, insertion, mergeMerge sort thought to sort inside sublists; merge phase left out; insertion sort confused with other sorts; “bubble sort is always better for small data”.

Merge sort: split to single items, then merge in order. Show it on the data given.

For example: Describe how a merge sort works. [3]

Weak It splits the list into halves and sorts each half.

Better The list is split in half again and again until each sublist has one item (1). Pairs of sublists are merged by comparing their first items and taking the smaller (1), until one sorted list remains (1).

P2 2022, P2 2023, P2 2024
2.3.1 Big O complexityO(n²) given as exponential; circular definitions (“grows exponentially”); “direct proportion” missing for linear; describing the best case; space complexity misjudged.

Exponential is O(2ⁿ). Describe how time (or memory) grows as n grows.

For example: Describe what is meant by O(n). [2]

Weak It is linear.

Better The time taken grows in direct proportion to the number of items (1): if n doubles, the time doubles (1).

P2 2022, P2 2023, P2 2024
2.3.1 Tree and graph traversal: breadth- and depth-firstBFS and DFS swapped; nodes listed in visit order instead of output order; weak backtracking; search confused with traversal.

BFS uses a queue, DFS a stack. Write the order the question asks for.

For example: Explain how a breadth-first traversal visits the nodes of a graph. [2]

Weak It goes across the graph.

Better It visits every neighbour of the start node first, adding each one to a queue (1), then takes the next node off the queue and visits its unvisited neighbours, so nodes are visited level by level (1).

P2 2022, P2 2023
2.3.1 Dijkstra’s and A*Answering “by inspection”; not continuing from the node with the least distance; start node not set to 0; overwritten distances not shown; A* treated like Dijkstra.

Show every step in a table. A* uses a heuristic and stops at the goal.

For example: Show how Dijkstra’s algorithm finds the shortest path from A to F. [6]

Weak A → C → F, total 9. (Found by looking: 1 mark at most.)

Better A table: A starts at 0 and the rest at ∞. Each step visits the unvisited node with the smallest distance and updates its neighbours, crossing out any distance that is replaced by a shorter one. Then read the path back from F.

Test yourself

Spot the examiner’s point – marked for you

1. “Caching makes the program faster.” Why might this score 0? AO1

Examiners want what is stored, from the scenario, and why it is quicker to get it again.

2. Which describes a relational database correctly? AO1

Examiners flagged “a number of related databases” as a misconception.

3. Which Big O is exponential? AO1

Candidates often gave O(n²), which is polynomial. O(2n) simplifies to O(n), which is linear.

4. In merge sort, when is the data put in order? AO1

Examiners report that many candidates think merge sort sorts inside the sublists.

5. A question says the scheduler uses round robin. Which answer to “name a scheduling algorithm” is worst? AO2

Never repeat an example the question has already given you.

6. Which is a correct statement of two features of recursion? AO1

Examiners report many stop at “calls itself” and miss the base case.
