Exam tips and improving your grade

OCR A Level Computer Science • H446

From B to A

Evaluate and connect. A-grade answers weigh up options, reach a justified conclusion and write complete, correct algorithms (AO3).

The big idea

Don’t just give both sides – decide. Say which side wins in this situation, and why.

What often holds a B grade back

  • Extended answers that list advantages and disadvantages but never decide.
  • Conclusions that just repeat earlier points, or “it depends” with no reason.
  • Algorithms that work for normal data but fail on edge cases.
  • Topics revised separately, so links between them are missed.

Six things to focus on

1. Plan extended answers

Use know it → apply it → judge it. One minute of planning saves a rambling answer.

2. Weigh, then decide

Say which factor matters most in this scenario. “X outweighs Y because…”.

3. Use exact technical language

“Iterative development with regular client feedback” beats “it’s flexible”.

4. Make synoptic links

Link topics: caching (2.1.2) to cache memory (1.1.1), data structures (1.4.2) to algorithms (2.3.1).

5. Write algorithms from scratch

Test them with normal, boundary and unusual data: empty lists, item not found, one item.

6. Mention efficiency

Name the algorithm and its Big O. Say when another would be better.

Before and after

Example 1

Reaching a justified conclusion

Question: A start-up is building a booking app. The client is not yet sure which features they want. Discuss whether the developers should use the waterfall model or an agile methodology. [9]

B-grade answer (extract) Middle band

Waterfall has clear stages and good documentation. Agile is flexible and the user is involved. Waterfall is good for big projects and agile is good for smaller ones. Both have advantages and disadvantages, so it depends on the project.

A-grade answer (extract) Top band

Because the client is unsure of the features, the requirements are likely to change. In waterfall, requirements are fixed at the start and going back to an earlier stage is costly, so new ideas would be expensive to add. Agile builds the app in short iterations, with the client reviewing a working version each time, so features can be changed as the client decides.

Waterfall’s documentation and fixed deadlines would help a start-up control costs, but this is outweighed by the risk of building the wrong product. Overall, agile is more suitable because unclear requirements make regular client feedback essential.

What made the difference:

  • Every point is applied to the client and the app.
  • Both methods are weighed against each other.
  • A clear conclusion that answers the question, with a reason.
Example 2

Writing a complete algorithm

Question: Write a function find that returns the index of target in the array items, or −1 if it is not there. [4]

B-grade answer Partial marks

function find(items, target)
    for i = 0 to items.length - 1
        if items[i] == target then
            return i
        else
            return -1
        endif
    next i
endfunction

Returns −1 as soon as the first item doesn’t match, so it only ever checks one item.

A-grade answer Full marks

function find(items, target)
    for i = 0 to items.length - 1
        if items[i] == target then
            return i
        endif
    next i
    return -1      // only after checking every item
endfunction

A linear search: O(n). If the array were sorted, a binary search would be O(log n).

What made the difference:

  • −1 is returned only after every item has been checked.
  • Tested against the edge case: target not in the array.
  • Efficiency named, with a better option for sorted data.

Best revision techniques for this step

  • Planning extended answers – structure 9 and 12 mark answers
  • Concept maps – build links between topics
  • Trace tables – test your own algorithms
  • Spaced practice and interleaving – mix topics like the exam does

These suit this step best, but use any technique that works for you.
